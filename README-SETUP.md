## Developer Paths

### Path 1 — First-Time Setup (fresh clone, empty database)

```powershell
git clone https://github.com/ghsansin/eaaf-automation.git
cd eaaf-automation
.\setup-dev.ps1
```

That's it. The setup script handles everything:
- Installs Node and Python dependencies
- Runs `npm run db:init` which creates the database AND loads all 21 questions from `rules/eaaf-questions.json`
- Starts the embedding service

No seed files to request. No separate seeding step. The database starts empty — see [Historical Assessment Data](#historical-assessment-data) if you need to load past assessments.

### Path 2 — Ongoing Development (already set up)

```bash
npm run dev                   # Start app (port 3000)
npm run embeddings:service    # Start embedding service in a second terminal (optional)
```

If your database is lost or corrupted:

```powershell
.\setup-dev.ps1 -Clean        # Rebuilds everything from scratch — questions reload automatically
```

Or manually:

```bash
Remove-Item data/app.db
npm run db:init               # Recreates schema and reloads all questions from config
npm run dev
```

## Question Configuration

Assessment questions, steps, factors, and sub-factors are defined in:

```
rules/eaaf-questions.json
```

This file is **tracked in git** and is the single source of truth for question content. Every time `npm run db:init` runs, it reads this file and upserts all question data into the database. No manual seed step is required.

| Key | Count | Description |
|-----|-------|-------------|
| `steps` | 5 | Assessment stages (ARCHITECTURE, CLOUD_ASSESSMENT, PLATFORM_ASSESSMENT, OPERATIONAL_CONSIDERATIONS, FINAL_RECOMMENDATION) |
| `factors` | 10 | Scoring factors grouped by step |
| `subFactors` | 16 | Sub-factors grouped by factor |
| `questions` | 21 | Questions, each with a stable `questionKey` |

**To add or change a question:** Edit `rules/eaaf-questions.json`, then run `npm run db:init`. The change syncs automatically. Add a matching scoring entry in `rules/eaaf-rules.json` if needed.

**Never remove a `questionKey`** that has existing responses — old rows are preserved in SQLite and responses depend on the `question_id` FK.

## Historical Assessment Data

Assessments are stored in `data/app.db` — a local SQLite file that is never committed to git. A fresh clone starts with an empty database.

### Preferred: copy the DB file

Copy `data/app.db` from the machine that has the data and drop it in the `data/` folder on the new machine. That's it — everything transfers, including embeddings and cached AI results. No extra steps needed.

> Back up before running `setup-dev.ps1 -Clean` — that command deletes `data/app.db`.

### Fallback: export / import

If you can't share the DB file directly, you can export a snapshot:

**On the machine with the data:**
```powershell
npm run export:assessments   # writes seed-data/assessments-seed.local.json
```

Share that JSON file, then on the fresh machine:
```powershell
npm run db:seed:assessments  # loads assessments + responses + recommendations
npm run embeddings:backfill  # regenerates embedding vectors for similarity matching
```

Keep in mind: the export captures assessment data and responses only — it does not include AI cache. That means the jurisdiction scan and innovative solutions panels will re-run (and make AI API calls) the first time each report is viewed.

## Step 2 — Run the Setup Script

From the `eaaf-automation` directory, run:

```powershell
.\setup-dev.ps1
```

This single command does everything:
- Enables PowerShell script execution if needed
- Creates a Python virtual environment and installs embedding service dependencies
- Installs npm dependencies
- Creates the SQLite database (`data/app.db`)
- Auto-syncs all question definitions from `rules/eaaf-questions.json` into the database (no seed file required)
- Starts the local embedding service on `http://127.0.0.1:8001`

### Available Flags

```powershell
.\setup-dev.ps1 -Clean            # Delete db, venv, and node_modules; rebuild from scratch
.\setup-dev.ps1 -StartDev         # Auto-start the Next.js dev server after setup
.\setup-dev.ps1 -SkipEmbeddings   # Skip starting the embedding service
.\setup-dev.ps1 -SkipSeed         # Skip data seeding (already seeded)
```

You can combine flags:

```powershell
.\setup-dev.ps1 -Clean -StartDev           # Clean rebuild and start dev server
.\setup-dev.ps1 -Clean -SkipEmbeddings     # Clean rebuild without embedding service
```

### "cannot be loaded" error

If PowerShell blocks the script, fix the execution policy first:

```powershell
Set-ExecutionPolicy -ExecutionPolicy RemoteSigned -Scope CurrentUser
```

The setup script also handles this automatically on its first run.

### Full Reset

If the database is corrupted or dependencies are stale:

```powershell
.\setup-dev.ps1 -Clean
```

This deletes `data/app.db`, `local-embedding-service\.venv`, and `node_modules`, then rebuilds everything from scratch.

## Step 4 — Start the Embedding Service (if needed)

The setup script starts the embedding service automatically. If it is not running in a subsequent session, start it manually in a second terminal:

```bash
npm run embeddings:service
```

It runs at `http://127.0.0.1:8001`. The app works without it — only the Similar Assessments feature requires it.

To restart it after stopping:

```powershell
# Kill any running Python processes first
taskkill /F /IM python.exe

# Then restart
npm run embeddings:service
```

The embedding service loads the `all-MiniLM-L6-v2` model on startup — this can take 15–30 seconds on first run. `setup-dev.ps1` polls the `/health` endpoint and waits up to 45 seconds before declaring it ready.

If the service fails to start, check the log:

```
local-embedding-service\embedding-service.log
```

## What Each Component Does

### SQLite Database (`data/app.db`)

Stores all application data:
- Assessment questions and step hierarchy (auto-synced from `rules/eaaf-questions.json` on every `db:init`)
- Assessment responses and metadata
- Historical assessment records for similarity matching
- Embeddings for similarity search
- AI result cache (jurisdiction scan, innovative solutions, assembled documents)

Initialized by `npm run db:init`. The `.gitignore` prevents it from being committed.

### Local Embedding Service (`http://127.0.0.1:8001`)

A local Flask server using the `all-MiniLM-L6-v2` sentence-transformer model.

What it does:
- Converts assessment response text into numerical vectors (embeddings)
- Compares a new assessment's embedding against historical ones
- Powers the "Similar Assessments" section on the recommendation report

Why it runs locally:
- Fully offline — no API key or external dependency
- Model chosen for good quality/speed balance on typical assessment text

Started automatically by `setup-dev.ps1`. Manual start: `npm run embeddings:service`.

## Troubleshooting

### "Python not found" during setup

```
⚠ Python not available — skipping embedding service
```

Install Python 3.8+ with "Add to PATH" checked, restart the terminal, then re-run `setup-dev.ps1`. The app still works without it.

### "pip install failed" during setup

```
✗ pip install failed
```

Install dependencies manually:

```powershell
cd local-embedding-service
.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

`sentence-transformers` and `torch` are large — first install may take several minutes.

### "Cannot find seed-data files"

If the health page warns about `seed-data/assessments-seed.local.json`, that file is optional. It is only needed to pre-load historical assessment data for the Similar Assessments feature. See the [Historical Assessment Data](#historical-assessment-data) section for the export/import workflow.

Question definitions are never missing — they live in `rules/eaaf-questions.json` which is tracked in git.

### Port conflicts

If port 3000 or 8001 is already in use, find and stop the other process, or change ports:
- Next.js: `npm run dev -- -p 3001`
- Embedding service: edit `local-embedding-service/app.py` and change the port value
